# Web version (static, in-browser search)

Everything runs in the browser: BM25, `multilingual-e5-small` query embeddings via transformers.js
(downloaded once, about 120 MB, then cached) and the same fusion logic as `qrt_rag.retrieval`.
No server and no reranker.

## Files

```
index.html       search interface: question, annex filter, excerpts with links to the EN and IT PDFs,
                 "copy prompt" for an AI assistant, feedback stored in the browser (exportable as JSONL)
js/search.js     WebRetriever: BM25 (rank_bm25 port), RRF fusion, code boost, implicit annex
js/embed.js      query embeddings with transformers.js
parity.html      parity test against the Python implementation
assets/          generated by qrt_rag.web_export.export_web() (notebooks/fase3_export_web.ipynb)
  chunks.json  embeddings.f16.bin  config.json  eval_set.json  parity.json
  regulation_en.pdf  regulation_it.pdf     (added by hand: the two official PDFs)
```

## Running locally

The pages load files with `fetch`, so they must be served over HTTP (opening the file directly does not work):

```bash
cd web
python -m http.server 8000
# then open http://localhost:8000/parity.html
```

## Collecting feedback (optional, Supabase)

Ratings are always stored in the visitor's browser. To collect them centrally:

1. Create a Supabase project and run `supabase/feedback.sql` in the SQL Editor: it creates the
   `feedback` table and lets the public key **insert only** (no reads, updates or deletes).
2. Fill in `feedback-config.json` with the project URL and the **public** key
   (anon / publishable). Never put the secret (service_role) key in the web app.
3. Read the collected feedback from Python with the secret key:

```python
from qrt_rag.feedback import fetch_supabase_feedback
fetch_supabase_feedback(URL, SECRET_KEY, "feedback_supabase.jsonl")
```

The resulting file has the same format as the Gradio feedback, so
`qrt_rag.evaluation.load_feedback_cases()` reads it directly.
